<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser → footer link targets | Footer links open user-clicked external destinations (GitHub Pages, social profiles); standard untrusted-link surface |
| Build pipeline → static asset | Liquid template renders `{{ site.footer_text }}` and other config values into HTML; Liquid auto-escapes by default but `footer_text` contains intentional HTML markup |
| PurgeCSS pass → compiled CSS | A misconfigured safelist could either over-include CSS (no security risk, just bundle bloat) or strip critical classes (functional regression on publication entries) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-03-01 | Tampering | `_config.yml` `footer_text` containing raw HTML | accept | The HTML is authored intentionally by the site owner and committed to git. Liquid does NOT auto-escape `{{ site.footer_text }}` because it is intended to render HTML — this is by design for the al-folio template. Tampering requires repository write access, out of scope for ASVS L1. |
| T-01-03-02 | Information Disclosure | Footer social handles linking off-site (GitHub, Scholar, LinkedIn) | accept | Outbound links are public-by-design; no PII leak beyond what every social link inherently exposes. Standard `target="_blank"` already managed by `social.liquid`. |
| T-01-03-03 | Denial of Service | Liquid template syntax error in `_includes/footer.liquid` breaking the build | mitigate | `bundle exec jekyll build` MUST succeed in Task 2's verify block. CI also runs the build on push and blocks deploy on failure. |
| T-01-03-04 | Tampering | PurgeCSS strips a critical class because it was missed in the safelist | mitigate | Task 3 includes `btn-primary-link` and `btn-outline-link` (used in `bib.liquid` on every publication page) plus `^footer-` (covers the new wrappers from Task 2). The verify block runs PurgeCSS and grep-checks for survival of both button classes. |
| T-01-03-05 | Information Disclosure | Open-redirect via `{{ site.url }}{{ site.baseurl }}{{ site.impressum_path }}` if `impressum_path` is attacker-controlled | accept | `impressum_path` is a Jekyll site config value committed to git, not user input. Standard al-folio pattern, unchanged by this plan. |
| T-01-03-06 | Spoofing | Footer link rel="noopener" / rel="noreferrer" not enforced for external nav links | accept | The footer-nav links go to internal pages (About, Publications, CV) so noopener/noreferrer is not relevant. Social links inherit their `target` and `rel` attributes from `social.liquid` which is unchanged. Hardening external-link rel attributes is out of scope for Phase 1; consider for Phase 4 (QUAL-*). |

No high-severity threats. ASVS L1 satisfied by build-pipeline gate (T-01-03-03) and explicit PurgeCSS safelist coverage (T-01-03-04).
