## Typography

The existing text scale in `_variables.scss` is preserved. New declarations add Inter as body font and Source Serif 4 as heading font.

| Role | Token / Size | Weight | Line Height | Font Family |
|------|-------------|--------|-------------|-------------|
| Body | `$text-body-size` = 1rem (16px) | 400 (regular) | `$text-body-line-height` = 1.65 | Inter |
| Small / Label | `$text-small-size` = 0.875rem (14px) | 400 (regular) | 1.5 | Inter |
| Caption | `$text-caption-size` = 0.75rem (12px) | 400 (regular) | 1.4 | Inter |
| Subheading (h3) | `$text-title-3` = 1.125rem (18px) | 600 (semibold) | 1.3 | Source Serif 4 |
| Section heading (h2) | `$text-title-2` = 1.5rem (24px) | 600 (semibold) | 1.25 | Source Serif 4 |
| Page heading (h1) | `$text-title-1` = clamp(2rem, 4vw, 3rem) | 400 (light-medium) | 1.2 | Source Serif 4 |

**Weight contract:** Body and labels use weight 400 only. Headings use 400 for h1 (elegant, not heavy) and 600 for h2/h3 (clear hierarchy). Weight 700 is loaded in the Google Fonts URL but not used as a default heading weight — reserve for bold emphasis within body copy only.

**Heading scope:** Source Serif 4 applies to `h1, h2, h3` ONLY. `h4`, `h5`, `h6` remain in Inter (sans-serif) to preserve hierarchy at small sizes.

**Google Fonts URL** (exact value for `_config.yml` `third_party_libraries.google_fonts.url.fonts`):
```
https://fonts.googleapis.com/css2?family=Inter:wght@400;500;600&family=Source+Serif+4:ital,opsz,wght@0,8..60,400;0,8..60,600;0,8..60,700;1,8..60,400&display=swap
```

**SCSS font-stack variables** (add to `_variables.scss` after the color block):
```scss
$font-sans: "Inter", system-ui, -apple-system, sans-serif;
$font-serif: "Source Serif 4", "Georgia", serif;
```

**CSS custom properties** (add to `_themes.scss` `:root` and `html[data-theme="dark"]` blocks):
```scss
--font-sans: #{$font-sans};
--font-serif: #{$font-serif};
```

**Application** (in `_layout.scss` body block and `_base.scss`):
```scss
// _layout.scss — inside body { } block
font-family: var(--font-sans);

// _base.scss — new rule near lines 43–56
h1, h2, h3 {
  font-family: var(--font-serif);
}
```

## Color

### 60/30/10 Distribution

| Role | Light Mode Value | Dark Mode Value | CSS Token | Usage |
|------|-----------------|-----------------|-----------|-------|
| Dominant (60%) | `#FAFAF8` warm off-white | `#1C1A24` plum-dark | `--global-bg-color` | Page background, all surfaces |
| Secondary (30%) | `#FFFFFF` white | `#252330` plum-card-dark | `--global-card-bg-color` | Cards, sidebar, content panels |
| Accent (10%) | `#5C4B8A` indigo-plum | `#9B8CC4` plum-light | `--global-theme-color` | Reserved for specific elements — see below |
| Text primary | `#1A1A1A` near-black | `#E8E3F0` warm-light | `--global-text-color` | All body copy |
| Text secondary | `#5E5A6E` warm-grey | `#9B95AA` muted warm | `--global-text-color-light` | Captions, metadata, labels |
| Dividers | `rgba(92,75,138,0.12)` | `rgba(155,140,196,0.15)` | `--global-divider-color` | Horizontal rules, borders |
| Hover / interactive | `#5C4B8A` | `#9B8CC4` | `--global-hover-color` | Same as accent — hover states only |
| Destructive | `#b71c1c` | (preserve existing) | `--global-highlight-color` | Award badges, destructive actions |

### Accent Reserved For (explicit list — not "all interactive elements")

The `#5C4B8A` accent is reserved ONLY for:
1. Navigation active/hover link color
2. External links within body copy
3. Button fills (`.btn-primary-link` PDF/code/poster buttons on publication entries)
4. Button outlines (`.btn-outline-link` secondary publication actions)
5. Blockquote left-border accent stripe
6. Publication venue badges and tags
7. Footer social icon hover state

The accent is NOT used for: card borders, background highlights, form focus rings (those inherit from Bootstrap), general icon color, or heading text.

### Footer Background

`--global-footer-bg-color` light mode: `#1C1A24` (plum-dark — matches dark-mode page background, creates visual anchoring). Dark mode: `#1C1A24` (unchanged — already appropriate).

### Bootstrap Override (conditional)

If Bootstrap-styled elements bleed the default blue (`--bs-link-color`), add to `head.liquid`:
```html
<style>
  body {
    --bs-link-color: var(--global-theme-color);
    --bs-link-hover-color: var(--global-hover-color);
  }
</style>
```
This is a conditional fix — apply only if Bootstrap link bleed is observed. Not a required change.

## Footer Design Contract

The footer redesign (D-13, D-14) is a light content + palette update, not a structural rebuild.

### Structure (both `fixed-bottom` and `sticky-bottom` branches)

```
[ copyright line ] [ attribution replacement ]
[ social icons via {% include social.liquid %} ]
[ nav links: About · Publications · CV ]
```

### Rules

1. Use `{% include social.liquid %}` for social icons — do NOT write hardcoded `<a>` tags for GitHub/Scholar/LinkedIn
2. Use `site.pages | where: "nav", true | sort: "nav_order"` for nav links — stays in sync with header nav
3. Keep `fixed-bottom` / `sticky-bottom` class structure — CSS depends on these classes
4. Edit BOTH branches (fixed and sticky) so the old attribution cannot reappear if `footer_fixed` is toggled off
5. Remove `{{ site.footer_text }}` only if `_config.yml` `footer_text` cannot be cleared; prefer clearing `footer_text` in config (step 1) over removing the Liquid variable from the template

### Footer Background Color

- Light mode: `--global-footer-bg-color` = `#1C1A24` (plum-dark)
- Dark mode: `--global-footer-bg-color` = `#1C1A24` (same)
- Footer text: use existing `--global-footer-text-color` and `--global-footer-link-color` (preserve)

## PurgeCSS Safelist Contract

The complete safelist addition for `purgecss.config.js`:

```javascript
safelist: {
  greedy: [
    /^hero-/,
    /^homepage-/,
    /^highlight-/,
    /^research-question-/,
    /^featured-publication/,
    /^project-story/,
    /^collaboration-cta/,
    /^btn-primary-link/,
    /^btn-outline-link/,
    /^cv-intro/,
  ],
},
```

The `greedy` option matches the class name itself AND compound selectors containing it (e.g. `.btn-primary-link:hover`, `.homepage-highlights .highlight-item`). This is the correct PurgeCSS pattern — do not use a plain `safelist` array.

Critical classes that must survive PurgeCSS: `btn-primary-link`, `btn-outline-link` (used in `bib.liquid` — publication entries on every page).

**Source:** CONTEXT.md D-15; RESEARCH.md `purgecss.config.js` section

## Implementation Sequence

Execute in this order to avoid regressions at each step:

1. **Color tokens** — `_variables.scss` (add plum primitives) → `_themes.scss` (update semantic tokens, both `:root` and `html[data-theme="dark"]`)
2. **Font loading** — `_config.yml` (replace Google Fonts URL)
3. **Font application** — `_layout.scss` (body `font-family`) → `_base.scss` (h1/h2/h3 `font-family`)
4. **Footer redesign** — `_config.yml` (`footer_text` clear) → `_includes/footer.liquid` (social icons + nav links)
5. **PurgeCSS safelist** — `purgecss.config.js` (add `safelist.greedy` block)

Verify locally after step 1 and step 2 before proceeding.
